# Семестровое задание: Анализатор логов

## Обзор

Разработать систему анализа логов, которая читает данные из различных источников, извлекает поля с помощью awk-подобного языка, фильтрует, агрегирует и формирует отчеты.

Система состоит из двух независимых DSL:
1. **DSL источников** — описывает откуда и в каком формате читать логи
2. **Awk-подобный DSL** — описывает как извлекать поля, фильтровать и агрегировать

Оба DSL являются embedded DSL на Kotlin: типизированы, проверяются компилятором, поддерживают автодополнение в IDE.

---

## Архитектура

- Sources DSL: `sources { json { file(...) http(...) } }`
- Awk-like DSL: `awk { field(...) BEGIN {...} pattern {...} END {...} }`
- Report: `OutputFormat` (JSON, CSV)

---

## Источники и форматы

### Источники (откуда читаем)

- **file** — локальные файлы
- **http** — HTTP-эндпоинты
- **udp** — UDP-сокеты (для syslog)
- **tcp** — TCP-сокеты (для syslog)

### Форматы (как парсим)

1. **JSON Lines** — построчный JSON, каждая строка — отдельный объект
2. **CSV** — разделитель настраивается, первая строка может быть заголовком
3. **Text** — строки, в которых поля разделяются регулярным выражением
4. **Syslog** — текстовый формат сообщений по UDP/TCP

---

## Формат Syslog

### RFC 5424 (новый)

Сообщение — строка с полями, разделенными пробелами:

`<priority>version timestamp hostname app-name process-id message-id structured-data message`

Поля:

- `<priority>` — приоритет (facility * 8 + severity)
- `version` — версия формата (обычно 1)
- `timestamp` — время в ISO 8601
- `hostname` — имя хоста
- `app-name` — имя приложения
- `process-id` — PID процесса
- `message-id` — идентификатор сообщения
- `structured-data` — структурированные данные в формате `[id key="value" ...]` или `-` если пусто
- `message` — текст сообщения

Пример с structured-data:

`<34>1 2026-01-15T10:30:00.123Z hostname app 1234 ID47 [meta auth="user1" retry="3"] DB connection failed`

Здесь structured-data — `[meta auth="user1" retry="3"]`, message — `DB connection failed`.

### RFC 3164 (старый, BSD syslog)

Сообщение — строка с менее строгой структурой:

`<priority>timestamp hostname tag[process-id]: message`

Пример:

`<34>Jan 15 10:30:00 hostname app[1234]: message text`

## Экранирование в логах

Переводы строк внутри полей экранируются как `\n`, а обратный слеш — как `\\`.

---

## Формат Text

В формате Text регулярное выражение задает **разделитель полей** в строке лога.
